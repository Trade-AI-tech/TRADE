## 1. ปัญหาคืออะไร — และทำไมมันไม่ใช่เรื่องของกลยุทธ์

R = กำไร/ขาดทุน **หารด้วยเงินที่เสี่ยงไปกับไม้นั้น**

ตัวหารของ R คือ **หน่วยวัด** ไม่ใช่ผลลัพธ์ ถ้าหน่วยเปลี่ยนไปเรื่อย ๆ ตามเหตุบังเอิญ
การเอา R หลายไม้มาเฉลี่ยกันก็เหมือนเอาราคาสินค้าหลายสกุลเงินมาบวกกันโดยไม่แปลงสกุล
— ผลลัพธ์เป็นตัวเลขที่คำนวณได้ แต่ไม่ได้แปลว่าอะไรเลย

โค้ดเดิมใช้ตัวหาร = `|ราคาเปิดแท่งถัดไป − SL|` ซึ่งมีสองอย่างผิดพร้อมกัน:

1. **มันถูกกำหนดหลังตัดสินใจไปแล้ว** ราคาเปิดแท่งถัดไปคือผลของ gap ข้ามคืน
   ซึ่งเป็นตัวแปรสุ่มที่ผู้เทรดไม่รู้ตอนกดสั่ง หน่วยวัดจึงถูกสุ่มใหม่ทุกไม้
2. **มันเล็กได้ไม่จำกัด** ถ้าราคาเปิดกระโดดมาเกือบทับ SL ระยะเหลือเป็นเศษเสี้ยว
   `backtest.ts` ทิ้งไม้เฉพาะตอนระยะเป็น **ศูนย์พอดี** เท่านั้น เศษเสี้ยวจึงผ่านเข้ามาได้

วัดจริงบน train (45,550 ไม้):

| สิ่งที่วัด | ค่า |
| --- | --- |
| ระยะเสี่ยงที่ "เหลือรอด" หลังราคาเปิด (realized ÷ planned) มัธยฐาน | 1.000 |
| — p10 | 0.835 |
| — p01 | 0.287 |
| — ต่ำสุด | 0 (3 ไม้ เปิดทับ SL พอดี) |
| — สูงสุด | 59.7 เท่า |
| ไม้ที่ระยะเหลือ < 20% ของที่ตั้งใจ | 309 (0.68%) |
| ไม้ที่ระยะเหลือ < 50% ของที่ตั้งใจ | 1,153 (2.53%) |
| ระยะ SL จริงต่ำกว่า 0.1% ของราคา | 156 ไม้ |
| ระยะ SL **ที่ตั้งใจไว้** ต่ำกว่า 0.1% ของราคา | 3 ไม้ |

บรรทัดสองบรรทัดสุดท้ายคือหัวใจ: ระยะ SL ที่สัญญาณ *ตั้งใจ* ไว้แทบไม่เคยแคบผิดปกติ
(p01 = 0.501% ของราคา เพราะกติกาของ signal-engine เองบังคับไว้ — ระดับแนวรับ/ต้าน × 0.995
หรือ 1.5×ATR) **ตัวหารที่เกือบเป็นศูนย์เกิดจาก gap ล้วน ๆ ไม่ได้เกิดจากสัญญาณ**

### ผลที่ตามมา: ไม้เดียวยึดค่าเฉลี่ยของทั้งชุด

| วัดบน train ทุกไม้ (R หลังหักต้นทุน) | ค่า |
| --- | --- |
| avgR | −9.4039 |
| \|R\| ของไม้เดียวที่ใหญ่ที่สุด | 423,625.7 |
| ไม้ 0.1% ที่สุดขั้วที่สุด คิดเป็นกี่ % ของ R รวม | **98.9%** |
| ถอดไม้เดียวออกแล้ว avgR ขยับได้สูงสุด | **9.30 R** |

avgR = −9.40 คือตัวเลขที่ **เป็นไปไม่ได้ทางกายภาพ** สำหรับระบบที่มี stop loss:
ถ้าทุกไม้มี SL อยู่ที่ 1R จะขาดทุนเฉลี่ย 9.4 เท่าของความเสี่ยงต่อไม้ไม่ได้
ตัวเลขนี้จึงไม่ใช่ "ผลที่แย่" แต่คือ **หลักฐานว่าเครื่องวัดพัง**

### ดูไม้เดียวให้เห็นภาพ: CPF 1D 2001-04-24 (ไม้ที่ R = 166.5)

| | ค่า |
| --- | --- |
| สัญญาณ BUY ออกที่ราคาปิด | 4.0500 · SL 4.0297 |
| ระยะที่ตั้งใจเสี่ยง | 0.0203 บาท/หุ้น = 0.50% ของราคา |
| ราคาเปิดแท่งถัดไป (เข้าไม้จริง) | 4.0300 ← กระโดดลง 0.49% |
| ระยะที่เหลือจริง | 0.0003 บาท/หุ้น = **1.5% ของที่ตั้งใจ** |
| ปิดไม้ที่ (time_exit) | 4.0800 → กำไร 0.05 บาท/หุ้น |
| **R นิยามเดิม** | 0.05 ÷ 0.0003 = **+166.55** |
| **R นิยามใหม่** | 0.05 ÷ 0.0203 = **+2.463** (หักต้นทุน 0.794 R เหลือ +1.669) |

ตัวเลขไหนคือเงินจริง: ผู้เทรดคิดขนาดไม้จาก 0.0203 บาท/หุ้น เพราะนั่นคือสิ่งที่เห็นตอนกดสั่ง
ไม้นี้จึงทำเงินได้ **2.46 เท่าของความเสี่ยงที่ตั้งใจ** ไม่ใช่ 166 เท่า
จะได้ 166 เท่าก็ต่อเมื่อกลับไปเพิ่มขนาดไม้อีก 68 เท่าหลังเห็นราคาเปิด ซึ่งไม่มีใครทำ
(และถ้าทำจริง ต้นทุนค่าคอมก็จะกินเกิน 100% ของ R ตามที่ตัวกรองในหัวข้อ 2 จับได้)

ไม้ AOT 1D 2012-05-21 ที่เคยได้ R = 108.78 ก็เช่นกัน → นิยามใหม่ได้ **+8.80** (สุทธิ +8.36)

## 2. ทำไมตัวเลขที่เคยรายงานถึงยังดูปกติ

รายงานเก่าไม่ได้รายงาน −9.40 แต่รายงาน **−0.0883** เพราะ `lab.mjs` มีตัวกรอง
"ไม้ที่เทรดได้จริง" (`costR(base) < 1` = ระยะ SL ต้องไม่แคบกว่าต้นทุนไปกลับ) อยู่ก่อนแล้ว
ซึ่งตัดไม้ 168 ไม้ที่ระเบิดออกไป

ต้องพูดตรง ๆ ว่าตัวกรองนั้น **ทำงานได้ผลจริง** — บนกลุ่มที่ผ่านตัวกรอง นิยามเดิมมีอิทธิพล
รายไม้เพียง 0.00061 R (train) แล้ว ไม่ใช่ 9.30

| กลุ่ม (train, net) | ไม้ | avgR | ไม้เดียวย้าย avgR ได้ |
| --- | --- | --- | --- |
| นิยามเดิม · ทุกไม้ | 45,547 | −9.4039 | 9.30085 |
| นิยามเดิม · เฉพาะกลุ่มที่ผ่านตัวกรอง | 45,379 | −0.0883 | 0.00061 |
| นิยามใหม่ · ทุกไม้ (ไม่ต้องกรอง) | 45,550 | −0.0838 | 0.00039 |

**แล้วทำไมยังต้องซ่อม ถ้าตัวกรองเอาอยู่แล้ว**

1. ตัวกรองนั้นผูกกับ **ตารางต้นทุนที่เป็นค่าเดา** เปลี่ยนตัวเลข bps เมื่อไหร่
   กลุ่มตัวอย่างเปลี่ยนตาม การเทียบผลข้ามรอบจึงไม่มั่นคง
2. ตัวกรองตัดไม้ทิ้งด้วยเหตุผลที่ **รู้ได้หลังเกิด gap แล้ว** = การเลือกกลุ่มตัวอย่าง
   ด้วยข้อมูลอนาคต ซึ่งเป็นสิ่งที่งานวิจัยนี้พยายามกันอยู่ทุกที่
3. บน validation นิยามเดิม **ยังทะลุตัวกรองมาได้**: ทุกไม้ ไม้เดียวย้าย avgR ได้ 0.0106 R
   = **35% ของขนาดผลที่งานวิจัยรอบนี้ตามหา (0.03 R/ไม้)** จากไม้เดียว
4. ทุกครั้งที่รายงานตัวเลขแล้วต้องต่อท้ายว่า "อันนี้คือกลุ่มที่ใจดีกว่านะ" คือหนี้ที่ต้องจ่าย
   ในทุกข้อสรุปหลังจากนั้น

## 4. ทางที่เลือก: (ค) หารด้วยระยะที่ตั้งใจไว้ตอนออกสัญญาณ

`R = (ราคาออก − ราคาเข้าจริง) × ทิศ ÷ |ราคาที่สัญญาณเห็น − SL|`

**เศษไม่เปลี่ยน** — กำไร/ขาดทุนยังคิดจากราคาเข้าจริงหลัง gap ทุกบาท
**ตัวหารเปลี่ยน** — จากระยะที่เหลือหลัง gap เป็นระยะที่ตกลงจะเสี่ยงตอนกดสั่ง

### ทำไมทางนี้

**1. มันคือหน่วยที่ผู้เทรดใช้จริง**
ขนาดไม้ = เงินที่ยอมเสี่ยง ÷ ระยะจากราคาเข้าถึง SL ผู้เทรดคิดขนาดไม้ตอนตัดสินใจ
โดยใช้ระยะที่เห็นตอนนั้น พอราคาเปิดกระโดด **ไม่มีใครกลับไปเปลี่ยนขนาดไม้** ดังนั้น
"เงิน 1R" ถูกล็อกไปแล้วก่อนเห็น gap — ตัวหารก็ต้องถูกล็อกตามนั้น

**2. มันทำให้ gap กลายเป็นความเสี่ยงจริง แทนที่จะหายไปในหน่วยวัด**
นิยามเดิมทำให้ไม้ที่ชน SL ได้ **−1.0000 R เป๊ะทุกไม้เสมอ** — โดยโครงสร้าง ไม่ใช่โดยข้อมูล
ความเสี่ยง gap ทั้งหมดถูกดูดหายเข้าไปในตัวหาร แล้วรายงานว่า "ทุกอย่างเป็นไปตามแผน"

| เหตุผลที่ออก (train, ก่อนหักต้นทุน) | R เฉลี่ย นิยามเดิม | R เฉลี่ย นิยามใหม่ |
| --- | --- | --- |
| stop_loss | **−1.0000 เป๊ะ** | −0.9744 |
| gap_stop | −1.1470 | **−1.1050** |
| take_profit | 1.1264 | 1.1008 |
| gap_target | 1.2423 | 1.2715 |
| time_exit | 0.2420 | 0.2101 |

นิยามใหม่ให้ค่าเฉลี่ยของ stop_loss = −0.9744 ซึ่ง *กระจาย* รอบ −1 แทนที่จะทับ −1 พอดี
ไม้ที่เปิดกระโดดหนีจาก SL เสีย **มากกว่า** 1R จริง ๆ และไม้ที่เปิดกระโดดเข้าหา SL
เสีย **น้อยกว่า** 1R จริง ๆ — ทั้งสองอย่างคือเงินจริงที่นิยามเดิมมองไม่เห็น

**3. ไม่มีค่าที่ต้องเลือกเอง**
ไม่มีเกณฑ์ 20% ไม่มีเพดาน ±5 ไม่มีอะไรให้จูน = ไม่มีช่องให้ p-hack ทีหลัง

**4. ไม่ต้องทิ้งข้อมูลจริงแม้แต่ไม้เดียว**
ตรงกันข้าม มันได้ไม้กลับมา 3 ไม้ที่นิยามเดิมทิ้งเพราะหารไม่ได้ (train 45,547 → 45,550)

### ทำไมไม่เลือกทางอื่น

**ทาง ก (ทิ้งไม้ที่ระยะเหลือน้อย) — ตกที่ด่านความเป็นธรรม**
ไม้ 309 ไม้ที่จะถูกทิ้ง เป็นไม้กำไรแค่ **4.2%** = ทิ้งไม้ขาดทุนเกือบล้วน
ต่อให้เจตนาดี ผลคือการทำให้ตัวเลขดูดีขึ้นด้วยการเลือกกลุ่มตัวอย่างจากผลลัพธ์
และเกณฑ์ 20% ก็เป็นตัวเลขที่เลือกเองอยู่ดี

**ทาง ข (ตัดที่ ±N) — แก้อาการ ไม่แก้เหตุ**
ตัดแล้วอิทธิพลรายไม้ต่ำที่สุดจริง (0.00011) แต่:
- N เป็นค่าที่เลือกเอง และ **ผลเปลี่ยนตาม N อย่างมีนัย** (วัดจริง avgR หลังหักต้นทุน):

| ±3 | −0.1201 | −0.1024 | −0.1131 | −0.0932 |
| ±5 | −0.1078 | −0.0907 | −0.1043 | −0.0846 |
| ±10 | −0.1031 | −0.0849 | −0.0985 | −0.0786 |
| ±20 | −0.1017 | −0.0838 | −0.0977 | −0.0777 |
| ไม่ตัด | −9.4039 | **−0.0838** | −0.1062 | **−0.0777** |

  อ่านคอลัมน์ "นิยามเดิม" จากล่างขึ้นบน: **ค่าไม่ลู่เข้าหาอะไรเลย** ไม่ตัดได้ −9.40
  ตัดที่ ±20 ได้ −0.1017 = คำตอบขึ้นกับ N ล้วน ๆ
  คอลัมน์ "นิยามใหม่" ลู่เข้าหา −0.0838 ตั้งแต่ ±10 ขึ้นไป (ต่างจากไม่ตัดเพียง 0.0011)
  → เพดานกลายเป็นสิ่งที่ **ไม่จำเป็น** แทนที่จะเป็นสิ่งที่ต้องเลือกให้ถูก
- มันตัดหัว 184 ไม้ แต่ตัดหาง 58 ไม้ = ไม่สมมาตร ทำให้ระบบดูแย่กว่าความจริง
- **ที่สำคัญที่สุด: มันไม่ได้แก้ว่าหน่วยวัดยังต่างกันทุกไม้อยู่ดี** ค่าเฉลี่ยยังเป็น
  การบวกของที่คนละหน่วย เพียงแต่ตัวที่เพี้ยนสุดถูกกดหัวไว้

**ตัดที่ ±5 บวกกับนิยามใหม่ก็ไม่เลือก** เพราะนิยามใหม่ทำให้อิทธิพลรายไม้ลงมาถึง
ระดับที่ยอมรับได้อยู่แล้ว การใส่เพดานเพิ่มคือการเพิ่มค่าที่ต้องเลือกเองโดยไม่จำเป็น

## 7. เครื่องวัดใหม่รับประกันอะไร และไม่รับประกันอะไร

### รับประกัน

- **ตัวหารถูกล็อกก่อนรู้ผล** ไม่มีตัวแปรสุ่มหลังตัดสินใจเข้ามาเปลี่ยนหน่วยวัดอีก
- **ไม่ต้องคัดกลุ่มไม้** ตัวเลขที่รายงานคือไม้ทุกไม้ (0 ไม้ถูกตัดออกทั้ง train และ validation)
- **อิทธิพลรายไม้บนกลุ่มขนาดเต็ม**: train 0.00039 R (1.3% ของขนาดผลที่ตามหา)
  · validation 0.00136 R (4.5%)

### ไม่รับประกัน — ต้องรู้ก่อนใช้

1. **ยังไม่มีขอบเขตตายตัวทางคณิตศาสตร์** ระยะ SL ที่สัญญาณตั้งเองยังมีหางบางที่แคบผิดปกติ
   (p01 = 0.501% ของราคา แต่ต่ำสุดที่วัดได้ 0.070% · 13 ไม้ใน train ต่ำกว่า 0.15%
   ซึ่งเป็นเกณฑ์ที่ `SIGNAL_GATE.minStopDistancePct` ของระบบจริงใช้อยู่แล้ว)
   ผลคือ \|R\| สูงสุดที่วัดได้ยังอยู่ที่ 17.8 (train) / 20.9 (validation)

2. **กลุ่มย่อยเล็กยังเปราะ** อิทธิพลรายไม้ ≈ \|R\| สูงสุด ÷ จำนวนไม้ ดังนั้นกลุ่มที่เล็กกว่า
   ~7,000 ไม้ ไม้เดียวยังย้ายค่าเฉลี่ยของกลุ่มได้เกิน 10% ของขนาดผลที่ตามหา
   → **กติกาบังคับ: ข้อสรุปใดที่ตัดสินด้วยส่วนต่างเล็กกว่า 0.01 R/ไม้ ต้องดูคอลัมน์
   "ค+ข: ตัดที่ ±10" ในตาราง "ตรวจเครื่องวัด" ของรายงานคู่กันเสมอ
   ถ้าข้อสรุปพลิกระหว่างสองคอลัมน์ นั่นคือผลของหาง ไม่ใช่ผลของกฎ — ห้ามรายงานว่าเจอ**
   (บน baseline สองคอลัมน์ต่างกัน 0.0011 R เท่านั้น: −0.0838 vs −0.0849)

3. **ยังเป็นการวัดบนกลุ่มตัวอย่างที่ไม่ใช่ประชากรทั้งหมด** กติกา "ถือทีละไม้" ยังตัด
   สัญญาณกว่าครึ่งทิ้งเหมือนเดิม การซ่อมนี้ไม่ได้แตะเรื่องนั้น

4. **ตัวเลขก่อน 2026-08-17 เทียบกับตัวเลขหลังจากนี้ตรง ๆ ไม่ได้** รวมถึงทุกตารางใน
   `diagnosis.md` ซึ่งใช้นิยามเดิม + คอลัมน์ "ตัดที่ ±5"

   > "1R = ระยะจากราคาที่สัญญาณคิดไว้ถึง SL (ความเสี่ยงที่ตั้งใจตอนออกสัญญาณ)
   > ไม่ใช่ระยะจากราคาเปิดจริง — ไม้ที่ราคาเปิดกระโดดหนีจาก SL จึงขาดทุนเกิน 1R ได้จริง
   > และไม้ที่กระโดดเข้าหา SL ก็ขาดทุนน้อยกว่า 1R"
   ควรผูกข้อความกับ `run.result.riskModel` ที่ API ส่งมาแล้ว ไม่ใช่ hardcode

2. **ป้าย "ชน SL" ในตารางไม้** — เดิมไม้กลุ่มนี้เป็น −1.00R เป๊ะทุกไม้ ตอนนี้จะเห็นค่า
   ตั้งแต่ราว −0.3R ถึง −2R ผู้ใช้ที่เคยชินกับ −1.00 จะคิดว่าโค้ดพัง ต้องมีคำอธิบาย

3. **ช่อง feesR** — คำอธิบายปัจจุบัน "สัดส่วนของ R เช่น 0.05 = 5% ของระยะ SL"
   ต้องแก้เป็น "5% ของระยะ SL **ที่ตั้งใจไว้**"

4. ถ้าเคยจดตัวเลขผลเก่าไว้เทียบ ต้องรู้ว่าเทียบกันไม่ได้แล้ว

### ⚠ `scripts/research/diagnose.mjs` — จะสอบตกที่ด่าน V2 (นอกขอบเขตรอบนี้)

V2 เทียบสำเนาลูป backtest กับ `runBacktest` ตัวจริงด้วย `a.r === b.r` ตอนนี้สองฝั่งใช้
ตัวหารคนละตัวแล้ว สคริปต์จะหยุดและไม่เขียนรายงาน (ซึ่งเป็นพฤติกรรมที่ออกแบบไว้ ไม่ใช่บั๊ก)

แก้ได้ด้วยการเติมบรรทัดเดียวที่การเรียก `runBacktest` ในฟังก์ชัน `verifyBacktestLoop`:
`riskModel: 'realized'` — แล้ว `diagnosis.md` จะยังสร้างได้เหมือนเดิมด้วยนิยามเดิม
หรือถ้าจะให้ `diagnosis.md` ใช้นิยามใหม่ ต้องแก้สำเนาลูปในไฟล์นั้นด้วยและรันใหม่ทั้งฉบับ

`scripts/build-speed-scorecard.mjs` และ `scripts/run-backtest.mjs` (`npm run backtest`)
**ไม่พัง** — ทั้งคู่รวมสถิติจาก `result.trades` ชุดเดียวกับที่เทียบ จึงตรงกันเสมอ
แต่ตัวเลขที่ออกมาเปลี่ยนความหมายตามนิยามใหม่ ถ้ามีผลเก่าจดไว้ ต้องรันใหม่ก่อนเทียบ

`npm run check:ui-claims` ผ่านทุกด่าน (รันแล้วหลังแก้) — ตัวตรวจนั้นดูข้อความ UI เทียบกับ
ข้อมูลของตัวเอง ไม่ได้ดูนิยามของ R จึงไม่จับข้อ 1–3 ข้างบนให้ ต้องแก้ด้วยมือ

### `scripts/research/lab.mjs` (แก้แล้ว)

- `--risk-model=planned|realized` (ค่าเริ่มต้น `planned`)
- ทุกไม้บันทึก `plannedRisk` `realizedRisk` `riskKeepRatio` `rGrossPlanned` `rGrossRealized`
- รายงานมีหัวข้อ **"ตรวจเครื่องวัด"** ที่แสดงทั้ง 5 ทางทุกครั้งที่รัน
  → ทุกการทดลองรอบต่อไปจะมีหลักฐานติดมาเองว่าไม้เดียวย้ายค่าเฉลี่ยได้แค่ไหน
- และหัวข้อ **"ตรวจความเป็นธรรมของการแก้"** ที่แสดงองค์ประกอบบวก/ลบของไม้ที่ถูกกระทบ
